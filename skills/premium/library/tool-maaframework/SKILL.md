# MaaFramework 图像识别黑盒自动化框架 技能卡

## 基本信息

- **中文名称**：MaaFramework 图像识别黑盒自动化框架
- **来源仓库**：[MaaXYZ/MaaFramework](https://github.com/MaaXYZ/MaaFramework)
- **上游参考分支**：`main`
- **参考提交（使用前核对）**：`ff51f411367aa2829852a4b675ee5ab824ab1fd7`
- **许可证线索**：LGPL-3.0（以 LICENSE.md 及第三方目录为准）；文件：`源码\LICENSE.md`

## 功能概览

1. 按图像/结构化资源定义识别、点击、滑动和条件分支任务
2. 提供跨平台控制器、任务流水线、回调、日志和可视化调试支持
3. 适合将重复 UI 流程组织为可重放的黑盒任务

## 适用范围

- 用于多步骤 UI 自动化、状态识别、任务编排和回放证据，尤其适合模拟器后台流程。

## 不能替代的边界

- 不提供进程内存、IL2CPP、native Hook、网络协议或游戏策略真值；识别/点击成功只说明 UI 层动作完成。

## 输入与输出合同

```text
输入：设备/窗口控制器、截图帧、任务 JSON/资源、超时、重试和回调配置。
输出：任务节点状态、截图、日志、回调事件、耗时和失败原因。
失败：控制器断开、资源未匹配、任务超时或回调异常时需停止当前流程、保存帧并交守护恢复。
后置：输出必须绑定项目、目标版本、平台/ABI（如适用）、时间戳和证据路径。
```

## 接入原则

1. 核对实际源码版本与说明中的参考提交后，先做最小、可撤销、可回放的接入。
2. 任何地址、线程、设备、模型、资源或协议输入都必须记录来源、版本和后置状态。
3. 工具输出是候选或观测，必须与项目专项规则、状态机和真实成功证据交叉验证。
4. 失败时保留原始错误和现场证据，不把命令退出码、识别命中或 Hook 安装当作业务成功。
5. 可与 OpenCV、PaddleOCR、MuMu API、scrcpy 组成 UI/采集层；不替代项目状态机和底层调用。
