# IL2CPP 类型恢复（Cpp2IL） 技能卡

## 基本信息

- **中文名称**：IL2CPP 类型恢复（Cpp2IL）
- **来源仓库**：[SamboyCoding/Cpp2IL](https://github.com/SamboyCoding/Cpp2IL)
- **上游参考分支**：`development`（本地固定提交为 detached HEAD）
- **参考提交（使用前核对）**：`1f59b73e27e8c614845107c24474f30fb881ba2b`
- **许可证线索**：MIT；文件：`源码\LICENSE`

## 功能概览

1. 解析 IL2CPP 元数据和二进制，构建托管类型、方法和 CIL 近似表示
2. 导出 DLL、控制流和构建报告，便于静态比对与命名恢复
3. 可作为 .NET/CLI 核心库嵌入自定义分析流程

## 适用范围

- 用于类型/方法结构恢复、版本差异分析和静态审查，补充 Il2CppDumper 的输出。

## 不能替代的边界

- 恢复的 CIL 可能不完整且不是原始源码；不提供运行时注入、函数调用、内存读写、线程调度或服务器状态判定。

## 输入与输出合同

```text
输入：匹配版本的 IL2CPP 二进制、metadata、目标平台、解析参数和输出目录。
输出：托管 DLL/CIL 近似、类型/方法表、控制流/构建报告和解析诊断。
失败：格式不支持、版本变化、元数据缺失或恢复失败时必须标记不完整，不能将近似 CIL 当作可执行逻辑。
后置：输出必须绑定项目、目标版本、平台/ABI（如适用）、时间戳和证据路径。
```

## 接入原则

1. 核对实际源码版本与说明中的参考提交后，先做最小、可撤销、可回放的接入。
2. 任何地址、线程、设备、模型、资源或协议输入都必须记录来源、版本和后置状态。
3. 工具输出是候选或观测，必须与项目专项规则、状态机和真实成功证据交叉验证。
4. 失败时保留原始错误和现场证据，不把命令退出码、识别命中或 Hook 安装当作业务成功。
5. 与 IL2CPP 静态分析、Ghidra、运行时桥接互补；类型恢复层不能替代运行时 ABI/生命周期门禁。
