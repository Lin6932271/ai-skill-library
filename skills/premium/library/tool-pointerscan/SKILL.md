# 指针链扫描（PointerScan）技能卡

## 基本信息

- **中文名称**：指针链扫描
- **来源仓库**：[niqiuqiux/PointerScan](https://github.com/niqiuqiux/PointerScan)
- **审查分支**：`newScan`
- **参考提交（需核对）**：`a763f03d9476b1554b803049d13fe5adc968a939`
- **仓库描述**：C++ 的 Android 进程内存指针链扫描工具
- **实现语言**：C++、Rust

## 能力范围

PointerScan 主要提供：

1. 从目标地址反向查找可能指向它的指针链。
2. 从源地址向目标地址做正向路径扫描。
3. 多线程扫描目标进程的可选内存区域。
4. 使用 DFS/BFS 构建多层指针链。
5. 以文本或二进制格式保存链路。
6. 比较不同运行或不同版本的指针链，筛选保持不变的链。
7. 通过 C++ 模板支持 64 位和 32 位指针宽度；Rust 版本面向 Android ARM64。

## 适合解决的问题

- 已知一个运行时对象、字段或数值地址，寻找可重复定位的根路径。
- 对比游戏重启、补丁升级或不同设备上的地址变化。
- 为只读状态采集建立模块相对根和偏移候选。
- 为 IL2CPP/Unity 对象定位提供候选链，再交给项目自己的对象校验和版本门禁。

## 不能替代的技能

- IL2CPP 元数据解析、类/方法签名确认和 `MethodInfo` 校准。
- Unity 游戏线程调度、Hook 安装和线程安全调用。
- NativeBridge、JNI、ARM64/x86_64 ABI 适配。
- 网络协议、服务端状态生成、请求回执和业务成功判定。
- 进程守护、闪退恢复、自动重开和工作 AI 生命周期。
- 任何“链存在”之外的功能成功证据。指针链命中不等于读值正确，更不等于动作执行成功。

## 方法说明与待核对事实

- C++ 读取路径包含 `process_vm_readv`，并可选用 `/proc/<pid>/mem` + `pread64`。
- 内存布局通过 `/proc/<pid>/maps` 解析，并按模块、匿名区、堆和代码/数据区域分类。
- C++ 构建使用 C++17，默认 CMake 目标写死为 Android `arm64-v8a`。
- CMake 中存在开发者本机 NDK 路径，接入其他环境前必须参数化。
- Rust 版本使用 `process_vm_readv`、`mmap` 文件后端队列和 Rayon 并行扫描。
- 仓库当前没有 GitHub Release，API 未返回 LICENSE 文件；使用前需要保留来源和许可核查记录。
- GitHub 当前存在开放 Issue #3，内容显示存在“扫描不到链”的实际使用问题，说明扫描结果需要项目级复核。

## 输入与输出合同

```text
输入：目标 PID/进程名、目标地址、最大深度、最大偏移、内存区域过滤
输出：模块根 + 偏移序列、文本/二进制链文件、跨版本比较报告
前置：目标进程和模块身份已确认，读取权限可用，地址来源有记录
后置：链文件带目标版本、ABI、PID/start_ticks、模块哈希和采样时间
失败：权限不足、区域不可读、地址失效、链为空或跨版本不稳定时标记失败/待验证
```

## 接入原则

1. 先保存目标地址的来源和语义，再进行扫描；禁止无来源地址盲扫后当作功能结论。
2. 先做小范围模块过滤和较浅深度，确认结果格式后再扩大扫描预算。
3. 链结果必须用新进程、新对局或新版本复测，至少检查根模块、每级偏移和最终值。
4. 记录完整读取错误和短读；不能把读取失败填零后的结果当作有效链。
5. 把 PointerScan 输出当作候选地址路径，交由目标项目的状态校验、生命周期校验和回读验证决定是否采用。
6. 不使用仓库预编译 `outputs/newscan` 作为发布依赖；按固定提交审查源码后，在目标 NDK 环境重新构建。

## 路由边界

- **l-gameassist** 负责目标游戏运行态和主流程；本技能只提供指针链候选扫描。
- **l-reverse** 负责逆向、类型和地址语义复核；扫描命中不等于字段语义正确。
- **build-release** 负责构建、依赖、产物和回滚；本目录源码不代表已构建或已部署。
