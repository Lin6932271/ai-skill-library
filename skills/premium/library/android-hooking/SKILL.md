# Android 运行时 Hook 与观测

用于当前用户明确指定的 Android 应用、设备和进程上的运行时观测。先确认任务需要的观察范围、目标身份及恢复方式，再选择 Java、JNI 或 Native 观察点。本文提供方法与示例，不证明设备、Frida、LSPosed 或其他工具已安装、已加载或已验证。

## 输入、输出与停止条件

输入：设备标识、包名、版本、APK 或模块摘要、ABI、进程 PID 与启动时间、需要观察的方法签名或导出符号、预期触发动作、日志目录和现有工具版本。

输出：目标身份记录、实际安装的观察点、带调用编号的 enter/leave/exception 事件、参数类型及长度摘要、原始错误、脱敏日志与对应用户操作。记录未命中、未执行和未验证项。

目标进程重启、模块版本变化、类加载器不匹配、方法重载不明、导出符号为空、指针范围未知、目标异常或无法卸载恢复时停止扩大观察范围，保留已有证据并重新定位。观察点安装、回调命中、行为解释和用户业务成功分别验收。

## 1. 核对现场环境与目标

1. 核对设备连接、目标包名及版本；区分主进程与应用的其他进程。检查 PID、启动时间和模块身份，避免复用进程重启前的地址。
2. 读取本机工具版本与帮助，确认现有 Frida 客户端、server 或 Gadget 的版本和设备 ABI，以及本次需要的 API 是否可用。使用当前工具支持的 attach/spawn 方式；不照搬旧版本的命令选项。
3. 检查当前设备已有的观测入口。设备准备、解锁、刷机、重签名、安装框架或模块是另外的环境操作，按用户要求处理；读取本技能不会执行这些步骤。
4. 静态确认类名、方法名、全部参数类型、返回类型和调用条件。混淆、多类加载器和 JNI 动态注册时，记录定位依据。

## 2. Java 重载观测

先枚举候选方法及其签名，选择一个与当前任务有关的重载。默认保留原参数、原返回值和原异常；先用用户可重现的操作建立无 Hook 的基线，再观察同一动作。

以下是说明性模板。`com.example.target.Api` 与 `sendData` 是占位示例；只有现场确认类加载器和签名后才替换使用。示例只记录输入长度及调用结果类别，不输出输入内容、凭据、网络请求头或个人信息。

下面为方法示例，需核对版本、输入与依赖后编译或运行验证；说明正文不表示已执行。

```javascript
Java.perform(function () {
    const Api = Java.use('com.example.target.Api');
    const method = Api.sendData.overload('java.lang.String', '[B');
    let sequence = 0;

    method.implementation = function (path, body) {
        const callId = ++sequence;
        send({event: 'enter', call_id: callId,
              method: 'sendData(String, byte[])',
              input_bytes: body === null ? null : body.length});
        try {
            const result = method.call(this, path, body);
            send({event: 'leave', call_id: callId,
                  result_kind: result === null ? 'null' : typeof result});
            return result;
        } catch (error) {
            send({event: 'exception', call_id: callId});
            throw error;
        }
    };
});
```

对照实际 Java 返回类型解释 `result_kind`，不能把 Java 包装对象的 JavaScript 类型当成业务类型。数组可能为空；若任务明确需要字节证据，先按现场 API 将 Java `byte[]` 显式转换为有界的字节数据并测试编码，不能直接假设可按 NativePointer 读取。构造函数同样选择精确重载并调用原构造函数。

## 3. JNI 边界

1. 从导出符号或 `RegisterNatives` 的实际记录确定 Java 方法、JNI 签名与 Native 实现的对应关系；区分静态注册、动态注册、静态 Java 方法和实例方法。
2. JNI 入口中的 `JNIEnv*`、`jobject/jclass` 与后续参数各有类型和生命周期。默认只记录签名、调用编号及已确认的类型/长度摘要，避免把 Java 对象引用作为普通内存地址解码。
3. 必须转换 `jstring` 或数组时，在有效调用现场核对线程、环境与对象有效性，检查异常和空值，配对释放临时资源。例如取得 UTF 字符串后需要对应释放；不能将局部引用跨线程或跨调用长期保存。
4. 关联 Java 与 Native 的同一调用事件；仅证明观察到该边界，不由返回值或日志直接推断服务器授权、保存成功等业务结果。

## 4. Native 观察点

1. 记录模块名、真实加载基址、文件摘要和架构；优先使用确认存在的导出符号。使用 RVA 时，证明其属于本次模块版本，核对计算后的可执行内存范围和目标指令。
2. 通过当前工具实际支持的 API 建立只观察的入口/退出回调；符号为空或目标尚未加载时等待相应加载证据，不能对未知地址安装观察点。
3. 参数与返回值的解码依照实际调用约定。缓冲区读取前确认指针、可读范围、长度上限及对象生命周期；未知指针只记录“不解码”，不试探任意内存。
4. 默认保持原执行路径，不替换实现、参数或返回值。改变行为的实验按具体用户任务单独设计，记录基线、影响范围与恢复操作。
5. 在最小观察点上触发一次已知操作，确认回调命中和目标正常，再决定是否需要更多观察点。性能测量可结合 [Perfetto](../tool-perfetto/SKILL.md)；崩溃证据可结合 [Breakpad](../tool-breakpad/SKILL.md)。

## 5. 日志、资源与恢复

日志保存为 JSON Lines，记录调用编号、时间、目标身份、阶段、签名、类型/长度摘要、证据路径和错误。限制队列大小、日志频率与磁盘占用；读取日志不能改变应用请求或响应。时间来自不同进程时记录各自时钟，不能未经校准直接计算跨进程延迟。

观察开始前登记本次句柄及原有 Hook 状态。退出时卸载本次 Native 观察点、恢复本次改变的 Java implementation，释放本次分配的句柄和引用，关闭本次日志文件；保留其他任务已有的观察点与设备配置。恢复后重复基线动作，并报告仍存在的异常。

## 验收记录

| 项目 | 需要的证据 |
|---|---|
| 目标一致 | 包名、版本、PID/启动时间、模块摘要与 ABI |
| Java 重载正确 | 实际类加载器、参数和返回类型、匹配的原方法调用 |
| Native 定位有效 | 导出或 RVA 来源、基址、内存范围和本次版本 |
| 观察命中 | 同一触发动作对应的 enter/leave/exception 事件 |
| 行为与恢复 | 原参数/返回/异常保持情况、卸载与基线复测 |
| 业务效果 | 当前用户请求对应的独立成功证据；未测时明确未验证 |

静态定位和 APK 结构核对使用 [APK 分析](../apk-reverse/SKILL.md)；跨 Android/iOS 的平台流程使用 移动应用分析（本版正文未取得）。本文补充细粒度观测，不取代它们，也不自动启动设备或执行示例。

## 接入前专项检查

- 核对当前 Frida 工具帮助、Java 重载与原方法显式调用，Java byte[] 日志采用有界转换。
- JNI 字符串取得与释放配对，Native 观测核对模块/RVA/ABI 与读取范围；保存脱敏日志并验证卸载恢复。
- 安装、加载、回调命中和用户功能结果分别验证；代码为未运行的说明性示例。
